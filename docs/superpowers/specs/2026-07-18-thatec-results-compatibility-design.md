# THATEC-compatible Results Explorer and result format

## Goal

Use the public THATEC HDF5 structure as the sole interchange contract. The application must open a real THATEC/eLab result such as `Elec_Det_20260606_RPTU0741_32P5_MTJcurrentSweep.h5` and a result generated by this application through one reader and one Results Explorer workflow.

Private application metadata may enrich a result, but it must never be required to read, visualize, or inspect the public experiment data.

## Compatibility contract

The reader treats the following THATEC structures as authoritative:

- `/scan_definition/tree_view` for experiment hierarchy;
- `/scan_definition/row_*` for parameter definitions, units, roles, and display metadata;
- `/measurement/row_*/data`, `timestamp`, `scale`, and optional `metadata` for acquired data;
- `/devices` for captured device configuration;
- `/labbook` for experiment metadata, comments, parameters, and pictures;
- `/post-process` for derived-data definitions.

It must not require `/run`, `/points`, `/spectra`, `/events`, or any other private group. If present, those groups are optional enrichments only.

The writer continues to emit valid THATEC groups and must ensure they contain enough information for the THATEC reader to describe the run without private data. Private state snapshots, simulation seed, and internal events remain namespaced extensions and are ignored safely by external THATEC tooling.

## Reader architecture

Introduce a THATEC-focused read model independent of the current private checkpoint reader.

`ThatecRunReader` exposes:

- an experiment tree reconstructed from `tree_view` and row definitions;
- typed row descriptors (identifier, control name, units, role, device, shape, timestamps, axes, and metadata);
- device records, labbook content, and post-process records;
- lazy scalar and spectrum access so a 5050 × 10001 real measurement is not loaded into memory at file-open time.

Existing private data remains available through an optional enrichment adapter. When a matching private checkpoint exists, Results can show its per-device state; when it does not, the generic THATEC device snapshot is shown instead.

## Results Explorer

The Results page is a three-pane inspector:

1. **Experiment tree** lists the hierarchy from THATEC verbatim, with explicit top-level nodes for Measurements, Devices, Labbook, and Post-process.
2. **Data workspace** renders a selected scalar row as a checkpoint table and trend plot, a spectrum row as a checkpoint selector plus spectrum plot, and textual/binary assets with safe summaries or previews. It never eagerly renders an entire large matrix.
3. **Inspector** presents the selected node's THATEC definition, units, shape, timestamps, device settings, labbook metadata, and optional application enrichment in structured key/value form.

The file list remains a convenient recent-results list, but selecting a file always invokes the THATEC reader first. An unreadable file reports the exact missing or malformed public structure rather than a private-schema error.

## Data flow

```text
HDF5 file
  -> ThatecRunReader
  -> experiment tree + lazy row handles + device/labbook/post-process records
  -> Results tree selection
  -> data workspace and inspector
  -> optional private enrichment, if available
```

## Error handling

- Missing optional groups produce an empty section, not an error.
- Missing required data for a selected row produces a local explanatory error while the rest of the file remains browsable.
- Dataset size is checked before loading; large two-dimensional datasets are sliced by checkpoint and downsampled only for display.
- Invalid public structure is surfaced with its HDF5 path and expected THATEC element.

## Verification

Tests must cover:

- parsing the real reference file's public tree, device records, labbook, post-process data, scalar rows, and 5050 × 10001 spectrum row without eagerly loading the full matrix;
- opening both the reference file and a generated simulation file through the same `ThatecRunReader` API;
- Results navigation from tree node to the correct workspace and inspector content;
- continued PyThat validation for generated files;
- writer assertions that all data needed for the public THATEC reader is emitted without reliance on private groups.

## Non-goals

- Reproducing eLab's entire editing interface.
- Mutating or repairing external result files.
- Treating application-private metadata as a THATEC requirement.
